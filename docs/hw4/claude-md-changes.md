# CLAUDE.md: /init output (v0.1) → v1.0

The original `/init` output is archived at `docs/hw4/init-output.md`.

## What /init missed (checked against docs/PRD.md)

| Gap | PRD source | Why it matters |
|---|---|---|
| PRD was referenced but not imported | whole doc | Claude had to remember to open it. With `@docs/PRD.md` it loads every session. |
| Nothing on the hold rule or volume gate | F3 AC2, AC4 | These are the logic most easily buried in a React hook, where it can't be tested. |
| Cents clamp (−50..+50) and input rejection (NaN, ≤0, out of range) | F2 AC2, AC4 | Edge cases are where test-first matters most. |
| Sharps and flats being the same note | F1 AC1 (21 chromatic notes) | Without one note representation, A#4 vs Bb4 bugs show up across the chart, detector, and songs. |
| Songs must be public-domain or original | F4 AC1 | An AI assistant will happily add copyrighted melodies. |
| Out-of-scope list | §5 | Stops scope creep (recording, other ocarinas). |
| P3 features (Auth.js, Postgres, teacher role) | F5, §3 | Needed to plan access control and validation. |
| Mic permission explanation and denied state | F3 AC1 | A required UX path, and one that needs a test. |
| No testing workflow beyond "colocate tests" | §6, HW4 TDD requirement | Didn't define red-green-refactor or the commit format. |
| No security guidance beyond one validation line | §7 | Didn't connect privacy requirements to concrete rules. |

## What I changed and why

| Change | Why |
|---|---|
| Restructured into the 8 required sections | Matches the HW4 rubric and splits facts (stack) from rules (conventions, do's and don'ts). |
| Added `@docs/PRD.md` import, kept `@AGENTS.md` | PRD is the source of truth. AGENTS.md carries the Next 16 warning and is regenerated by `next dev`. |
| Removed the "Current state: no feature code yet" line | It goes out of date after the first feature commit. |
| Removed the Permissions section | It repeated `.claude/settings.json`. Kept only the "don't" rules Claude would otherwise hit as denials. |
| Turned "intended architecture" into 8 numbered decisions | Gives each decision a reason and makes it easy to point to (e.g. "violates decision 3"). |
| Added the audio adapter split (decision 3) | Puts every PRD rule that needs a mic behind pure functions, so tests never need a microphone (PRD §6). |
| Added coding conventions: result unions, unit-suffixed names, `@/` imports, `"use client"` only where needed | /init had none. These are the choices most likely to drift between sessions. |
| Added TDD table with `[red]` / `[green]` commit tags and AC IDs | Makes the red-green-refactor history visible in `git log` for grading. |
| Added fake-timer and mock-`getUserMedia` testing rules | Covers the two parts of the app that are hard to test (timing and the mic). |
| Added OWASP Top 10 (2025) table, only rows that apply | Turns PRD §7 into concrete rules. I left out A04 (cryptographic failures) and A08 (software/data integrity) because Auth.js and Vercel handle them. |
| Added a rule to cite the fingering chart's source | Fingerings written from model memory could be wrong, and a wrong fingering is a real bug for learners. |
| Added Rules changelog | Tracks future edits to these rules. |

Length: v0.1 was 51 lines; v1.0 is 110 (limit 150).
